    The problem

    Players understand timestamps. People remember moments.

    You never think “go to 2:12”. You think “his goal”, “the line where she says two minutes left”, “what did I miss?”. Today the remote can only skip ten seconds, so you hold rewind, overshoot and try again.

    With a remote

    Rewind 10 s. Too far. Forward 10 s. Missed it. Forty seconds later you find the build-up, and the moment has passed.

      How it works

      Understand, ground, act, remember, continue.

      Follow one request through the loop. The AI model is used where meaning is ambiguous. Everything after the moment is found is exact and deterministic.

      1. 1

        Understand

        The Context Envelope tells the agent what is on screen, what you just asked about and how far you've watched.

        “his” → Usain Bolt
        spoilers up to 2:27
      2. 2

        Ground

        Hybrid search over the index built with Amazon Rekognition picks the moment, then starts it on the build-up.

        moments.search
        → Usain Bolt scores first goal @ 2:12
      3. 3

        Act

        A precise command reaches the Fire OS app over our player bridge, and ExoPlayer executes it natively.

        player.seek 2:12 → play
        243 ms
      4. 4

        Remember

        The moment is saved to your Viewing Memory in Amazon DynamoDB and mirrored to Bedrock AgentCore Memory.

        semantic_seek · Usain Bolt
      5. 5

        Continue

        Follow-ups are relative to the grounded moment, so “five seconds earlier in slow motion” is exact maths.

        seek −5 s · speed 0.5×
        772 ms, no model

      Accessibility · open source

      We went to fix captions in our app and found them broken for every React Native Fire TV app.

      People who rely on captions, or on Audio Description (a narrator describing the picture for blind and low-vision viewers), turn it on once in Fire TV settings. Apps are supposed to follow it. Our native app did. Amazon's React Native starter for TV apps didn't, and a bug underneath meant subtitle files never loaded on Android at all.

      FAQ

      Questions people ask first.

      Is the demo real?

      Yes. Every clip is a screen recording of our Fire OS app (Kotlin, Media3 ExoPlayer) on the Android TV emulator, API 30, which is the Android base of Fire OS 8. The steps next to each clip come from the trace our server saved for that request. Requests were sent by a script through the same endpoint typed or spoken input uses.

      Is this Alexa+?

      No. Alexa+ is the voice front end we designed for. We built the part it connects to: a self-hosted MCP server (spec 2025-11-25, Streamable HTTP, 26 tools). Alexa+ add-on tools are partner-only, so our own agent calls the same server today.

      Does it spoil things?

      No. The spoiler boundary moves only with real playback. Search, catch-up and open questions never use moments after it until you say “spoilers off”, and that rule lives in code rather than in a prompt.

      Which videos does it work with?

      Any video that has been indexed. The demo uses Creative Commons titles: Soccer Aid for UNICEF 2023 highlights, Tears of Steel, a cooking video and a TEDx talk, plus a live Amazon IVS channel. Each title's index is built once, at ingest.

      What does it use AWS for?

      Amazon Rekognition for shots, faces, on-screen text and film characters. Amazon Polly for every spoken answer. Amazon DynamoDB and Bedrock AgentCore Memory for Viewing Memory. Amazon IVS for the live channel and its goal markers. Amazon S3 for media. Bedrock is integrated as the agent's model and switches on when the account is enabled.

      Can I run it?

      Yes, without an AWS account. The repository ships compact copies of the six titles, and features that need AWS say so when it's missing. The code is on GitHub under the MIT licence.
